Conn and Params

Every action gets a Conn: the parsed request. Ticket.Params reads values out of it with Rails' precedence.

Conn

A Conn is an immutable record that the router builds once per request. Filters that change it return a new one with { ..conn, … }.

types
  Conn = {
    request: Request,
    method: String,          // upper-cased
    path: String,            // without the query string, "/" at least
    segments: List<String>,  // "/posts/3/" is ["posts", "3"]
    path_params: Map<String, String>,
    query: Map<String, String>,
    form: Map<String, String>,
    cookies: Map<String, String>,
  }

Conn.header(conn, name) reads a header, ignoring case, and returns "" when it's missing.

Reading params

Lookups check the path first, then the form body, then the query string, like Rails' merged params.

FunctionReturns
Params.string(conn, key)Option<String>
Params.int(conn, key)Option<Int>, None when it's missing or not a number
Params.id(conn, key)Option<Id<a>>
Params.nested(conn, prefix)A Map of the prefix[key] fields
// POST /articles with body article[title]=Hi
let title = Option.with_default(Map.get(Params.nested(conn, "article"), "title"), "")

Parsing rules

  • The form body is parsed only for application/x-www-form-urlencoded. A JSON body stays in conn.request.body for Json.decode.
  • Keys and values are percent-decoded, and + becomes a space.
  • When a key appears twice, the last one wins.
  • Params.nested goes one level deep. Lists like tags[]=a aren't supported yet.
  • Cookies come from the cookie header, with values percent-decoded.

Coming in F2: typed strong params. Params.record(conn, "post") will decode the post[…] fields straight into a record, with field errors for missing or ill-typed values.
