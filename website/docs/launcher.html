Launcher and Tasks

Ticket ships a launcher: the Node program that serves your app when you run polar run or polar start. It also runs tasks.

Serving

Set launcher = "ticket" under [run]. The launcher loads your built app, calls its exported router for each request, and answers 404 when it returns None. 

[run]
launcher = "ticket"
options = { port = 3000, env = "development" }
Option Default What
port 3000 Port to listen on
hostname "127.0.0.1" Address to bind
env "development" puts the error's stack in the body of a 500
server "Node" Host the router runs on
client "Browser" Host whose bundle is served to the browser, if the app has one

Tasks

polar start -- <task> runs a task against the built app instead of serving it.

Task What
routes Prints the route table: helper, method, path and action. Exits 0.
db:migrate, db:rollback, db:status, db:reset, db:seed Run the app's migrate and seed. See Database. 
$ polar build
$ polar start -- routes
  root_path         GET   /              PagesController.home
  about_path        GET   /about         PagesController.about
                    GET   /boom          PagesController.boom
  articles_path     GET   /articles      ArticlesController.index
  new_article_path  GET   /articles/new  ArticlesController.new
                    POST  /articles      ArticlesController.create
  article_path      GET   /articles/:id  ArticlesController.show
  admin_stats_path  GET   /admin/stats   StatsController.show

An unknown task exits 2 and lists the known ones. F2 adds db:migrate, db:rollback and friends here.

In production

Set TICKET_ENV=production and a TICKET_SECRET. PORT and HOST set the address. ticket new writes a Dockerfile that does all of this.

  • GET /up answers 200 ok without touching the session or the database, for a liveness check.
  • SIGTERM and SIGINT stop accepting, finish in-flight requests and exit 0. A second signal, or [server] shutdown_timeout seconds (10 by default), cuts them and exits 1.
  • Every response carries x-content-type-options: nosniff, x-frame-options: SAMEORIGIN and referrer-policy: strict-origin-when-cross-origin, unless the action sets its own. Content-Security-Policy is opt-in.
  • [server] log is json in production (one object per request, with an x-request-id) and text in development. off silences it. 
$ docker build -t my_app .
$ docker run -p 3000:3000 -e TICKET_SECRET=... my_app

The CLI wraps this: ticket server -p 3000 runs the app and ticket routes builds and prints the table.
