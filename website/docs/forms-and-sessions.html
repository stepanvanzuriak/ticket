Forms and Sessions

Forms are JSX components. Sessions are one signed cookie that holds the session, the flash and the CSRF token.

Forms

Ticket.Forms and Ticket.Links are view_component zones. A form's fields are its children, and each field renders a label, an input and its messages in a div.field, with field_with_errors when it has any.

views
  form(conn: Conn, fields: Map<String, String>, errors: Errors)
    <Forms.Form conn={conn} action={Paths.posts_path()}>
      <Forms.ErrorSummary errors={errors} noun="post" />
      <Forms.TextField prefix="post" field="title" value={Forms.value(fields, "title")} errors={errors} />
      <Forms.TextArea prefix="post" field="body" value={Forms.value(fields, "body")} errors={errors} />
      <Forms.Checkbox prefix="post" field="published" checked={Forms.checked(fields, "published")} errors={errors} />
      <Forms.Submit text="Create post" />
    </Forms.Form>

The components are Form, MethodForm (patch, put, delete add a hidden _method), TextField, TextArea, EmailField, NumberField, PasswordField (never renders its value), HiddenField, Checkbox, Select, Label, Submit and ErrorSummary, plus Links.LinkTo and Links.ButtonTo (a one-button form, how a delete works without JavaScript). All text is escaped.

A failed Params.record keeps nothing, so a re-render passes Params.nested(conn, "post") as fields to show what was typed.

Sessions and flash

A controller action calls Session.handle(conn, action). It loads the cookie (a bad signature or an expired one is an empty session), refuses an unsafe request without a CSRF token, and writes the cookie back when the session is new or a flash was shown.

create(conn: Conn) -> Response / {Posts, Throws<DbFailure>, Process, Random, Clock} {
  Session.handle(conn, save)
}

save(conn: Conn) -> Response / {Posts, Throws<DbFailure>} {
  Response.redirect_to(
    Flash.put(conn, "notice", "Post was created."),
    Paths.post_path(Posts.insert(row).id),
  )
}

Flash.put shows on the next page once; Flash.get(conn, "notice") reads it. Session.put and Session.get work on the same cookie, which is signed, not encrypted: don't store secrets in it. Csrf.meta(conn) goes in the layout's <head>, and forms carry the token field themselves.

SettingWhere
Secret[session] secret in ticket.toml, or TICKET_SECRET. Production refuses to start without one when [session] exists.
Lifetime[session] max_age (seconds, 14 days by default)

Static files, log and error pages

Files under public/ are served at the root before the router (GET and HEAD, never outside the folder, never dotfiles). Production caches for an hour with an ETag; development sends no-cache. Every request logs one line, with form and JSON params and secret-looking keys shown as [FILTERED]:

Started POST "/articles" 422 (9ms)  params={"article":{"title":""}}

A failure in development shows a page with the message, stack and params. In production public/500.html and public/404.html are served to browsers. [server] in ticket.toml sets public, log ("request" or "off") and filter_params.
